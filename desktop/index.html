CONNECTION & TRUST

연결 설정

실험실과 별도 배포한 서비스의 연결을 구분합니다.

연결 모드

원격 서비스는 사전에 확인한 U 설정 파일로 연결합니다. 설정에는 고정된 공개키·TLS CA·허용 경로가 포함되어야 합니다.

OPERATOR OWNED KEYS

배포와 키

각 운영자가 자기 환경에서 키를 생성하고, 동일한 배포 지문을 확인한 뒤 승인합니다.

1. 로컬 신원 생성

공유할 파일은 operator.json입니다. 개인키와 운영자 폴더는 해당 운영자의 PC에 보관합니다.

2. 배포 제안 만들기

U/R/M/T의 공개 카드 4개, 목격자를 쓸 경우 W 카드까지 합칩니다. 각 운영자의 지문은 별도 연락 경로에서 확인해야 합니다.

키 교체·새 정책 세대로 이어가기

새 세대의 제안은 이전 배포 해시·체크포인트를 포함합니다. 이전 키와 새 키가 모두 승인해야 합니다.

3. 검토한 제안에 서명

4. 승인 모으기

5. 검토한 배포 활성화

키 교체 전 진행 요청·증거 제출을 마치고 이전 감사 자료와 체크포인트를 보관하세요. 활성화하면 해당 역할의 이전 설정은 새 요청을 거부합니다. 반환된 config.json으로 서비스를 다시 실행하고 U는 ‘연결 설정’에서 적용합니다.

단계별 결과와 저장 경로가 표시됩니다.

AUDIT BEYOND T

감사 자료와 운영 점검

외부 감사·목격자·보관 정책을 현재 연결에 적용합니다.

연결 능력과 목격자

각 역할의 TLS·서명 신원을 점검합니다. W는 체크포인트의 이전 이력을 검사하며 본문을 받지 않습니다.

목격자 영수증과 앵커 해시를 파일로 저장합니다. 블록체인 게시를 수행한 결과가 아닙니다.

외부 감사용 내보내기

신뢰 기준은 자료와 별도로 확인해야 합니다. 공개 패키지에는 salt·비솔트 해시가 없고 비공개 등식은 미검증으로 남습니다.

암호화 패키지는 요청별 salt·원문 해시를 포함하므로 지정한 감사자에게만 전달하세요. 원문·개인 서명 키는 포함하지 않습니다.

받은 패키지 재검증

로컬 본문 보관 정리

기본 30일이 지난 요청의 본문·비공개 감사 입력을 정리합니다. 제출 대기 증거와 서명·집행 기록은 유지합니다. 정리 후 전체 비공개 감사에는 이전에 저장한 암호화 패키지가 필요합니다.

검증 결과와 저장 경로가 표시됩니다.
