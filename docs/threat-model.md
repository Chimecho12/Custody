# 위협 모델

## 역할

| 역할 | 하는 일 | 발행 진술 | 신뢰 가정 (첫 버전 TM1) |
|---|---|---|---|
| U 사용자 | 요청 생성, 계약 서명, 응답 수신·검증·집행 | 요청 계약, 수신 진술, 세션 매니페스트 | 정직. 키 관리는 취약할 수 있음 |
| R 중개자 | 요청·응답 전달·변환·라우팅 | 중계 진술 | **신뢰하지 않음.** 변조·바꿔치기·숨은 폴백·누락·재전송·지연 모두 가능 |
| M 모델 운영자 | 추론 실행, 영수증 발행 | 추론 영수증 (AIR-02 유사, evaluation 고정) | 입출력 **관측은 정직**. 실행 증명은 별도 (아티팩트 ≠ 실행) |
| T 제3자 | 진술 등록, 영수증 발행, 대조, 판정 발행, 체크포인트 | 등록 정책, 판정 진술 | 구조적으로 투명. 오판·침해 가능성을 **가정하고** 감사로 드러냄 |
| 감사자 | T 내보내기·앵커·권한 증거 묶음으로 재실행 | — | T 의 코드를 믿지 않음 |

## TM1 (첫 실험군)

> U 의 집행 모듈과 M 의 입출력 관측은 정직하며, R 은 악성일 수 있다.

이 가정 아래서 위반 등식의 귀속은 R 이다. 판정의 `attribution_basis` 필드는 항상 이 가정을 함께 적는다.
서명 검증은 "누가 서명했는가" 를 확인할 뿐 "정직하게 관측했는가" 를 확인하지 않기 때문이다.

## TM1 밖 (별도 실험군으로 표시)

| 사건 | 시나리오 | 현재 결과 |
|---|---|---|
| R 과 M 이 공모해 일치하는 거짓 진술 | S15 | 모든 등식 통과. **탐지 불가** 로 표시 |
| T 가 잘못된 판정 발행 | S13 | U 로컬 검증이 격리, 독립 감사가 불일치 발견 |
| T 가 기록을 재작성 | S14 | 외부 앵커·일관성 증명 불일치로 발견 |
| T 가 요청 항목을 누락하고 재서명 (앵커 이전) | S18 | 트리·헤드·앵커·판정 재실행은 전부 자기 일관적. **U·R·M 이 각자 보관한 등록 영수증**의 포함 검사만 발견. 영수증을 버린 당사자의 항목 누락은 보이지 않는다 |
| M 이 거짓 관측을 서명 (단독) | 미구현 | E3·E6 모순으로 'R 또는 M' 까지만 좁힘 |
| U 키 침해 | 미구현 | — |

## 공격자가 바꿀 수 있는 것 / 없는 것

| 실험 | 바꿀 수 있음 | 바꿀 수 없음 |
|---|---|---|
| 요청·응답 변조 | R 이 전달하는 본문, R 의 선언 | U 의 계약·솔트·nonce, M 의 서명 키 |
| 라우팅 | 상위 모델, 폴백 선언 | U 의 허용 집합 |
| 재전송·누락 | 전달 여부, 이전 응답 재사용 | attempt_id·nonce 발급 |
| 증거 | 자기 진술의 발행 여부·내용 | 타인의 서명, 로그의 과거 |
| 가용성 | (시나리오) T 정지·지연, 큐 용량, **R 의 진술 보류** | 사용자 모드 선택, 적체 정책 |

## 가용성 정책 (무결성 검사가 가용성 스위치가 되지 않게)

| 압박 | 기본 동작 | 정책 |
|---|---|---|
| R 이 중계 진술을 보류 (S09, 런타임 `missing_relay`) | 결손은 위반이 아니다. protect 는 U+M 증거로 계속하고 strict 는 T 의 gap·passed 판정으로 수용한다 | `require_relay_statement: true` 로만 격리로 바꾼다. 이 정책은 "R 이 진술을 안 내면 전부 격리" 라는 서비스 거부 스위치를 R 에게 쥐여 주는 선택이므로 기본값이 아니다 |
| T 정지·지연 (S10·S11) | protect 계속, strict 는 기한 내 거부 | `strict_timeout_ms` |
| 증거 큐 포화 (S12, 런타임) | 시뮬레이션: 오래된 증거를 버린다(drop_oldest). 런타임: 기존 증거는 절대 버리지 않는다 | 런타임 `evidence_backlog_policy` — `bounded`(기본): 한도(`queue_capacity`)를 넘기면 새 요청을 거절한다. 기록할 수 없는 약속은 하지 않는다. `unbounded`: 요청 보관 한도까지 계속 쌓는다 |

지표 `availability_legit`·`availability_under_pressure` 가 이 표의 결과를 모드별로 센다. 오차단·안전 완료는
"정상 요청을 막았는가" 를 재지만 "R 이나 T 가 협조를 거두면 정상 요청이 어떻게 되는가" 는 재지 못했다.

## 다루지 않는 것

- **기밀성.** R 이 프롬프트를 보관·학습에 썼는지는 어떤 등식으로도 알 수 없다.
- **DoS·메타데이터.** 타이밍·크기·빈도는 숨기지 않는다. 전면 DoS 방어는 범위 밖이다.
- **실행 수준 모델 바꿔치기.** 아티팩트 해시 일치(E9)는 실행 일치가 아니다. 통계 검증은 후속.
- **실제 TEE.** 모든 증명 문서는 mock. 보증은 최대 `air-local`.

## 협조 집합과 확립 가능한 것

| 협조 | 있는 증거 | 확립 가능 | 확립 불가 |
|---|---|---|---|
| U | 계약, 수신 진술, 비공개 증거 | E1, E12 | 무결성 전부 (insufficient_evidence) |
| U+M | + 영수증 | E1, E4(M 관측 기준), E5, E8, E9, **E10**, E11, E12 | 중계 선언 관련(E2·E3·E6·E7). 완전성은 gap |
| U+R | + 중계 진술 | E2, E7, E8(자기 주장), E12 | **E10** → 종단 무결성 확립 불가 |
| U+R+M | 전부 | E1~E12 | 공모 |

Q1 매트릭스(`run_q1_matrix`)가 이 표를 실측(모의)한다.
