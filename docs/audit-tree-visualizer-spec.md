# 제3자 검증 (트리·앵커·판정) 시각화 & JSON 양방향 매핑 UI 설계서

본 문서는 `itx` 데스크톱 앱의 '제3자 검증(`view-audit`)' 화면에서 원시 JSON 덤프(`<pre>`)로 제공되던 트리·앵커·판정 데이터를 직관적인 시각 다이어그램으로 전환하고, JSON과 실시간 양방향 매핑하는 UI/UX 사양을 정의합니다.

---

## 1. 문제점 및 설계 목표

* **기존 문제**:
  - `replay_audit()`의 결과가 단순 통계 수치와 500줄 이상의 거대한 원시 JSON(`<pre>`)으로 출력되어, 머클 트리의 구조, 과거 앵커와의 일관성, 재실행 판정 불일치의 원인을 직관적으로 파악하기 어려움.
* **설계 목표**:
  1. **머클 트리(Merkle Tree) 및 체크포인트 앵커(Anchor)**의 추가 전용(Append-only) 구조를 시각적 분기 그래프로 렌더링.
  2. **T의 판정 vs 감사자의 독립 재계산 판정**을 나란히(Side-by-side) 대조하여 불일치(S13) 시 즉각적인 원인 식별.
  3. **좌측 다이어그램 ↔ 우측 JSON 인스펙터 간 실시간 양방향 하이라이트 및 자동 스크롤(Auto-scroll)** 구현.

## 3. 핵심 컴포넌트 상세 사양

### 3.1 머클 트리 & 앵커 브릿지 (`MerkleAnchorBridge`)
1. **Tree Head & Root Node**:
   - T가 서명한 헤드 해시와 감사자가 로그 진술들을 재해시하여 계산한 루트 해시를 상단에 배치.
   - 두 해시가 일치하면 연결선이 초록색(`--pass`)으로 이어지며 방패 체크 아이콘 표출.
   - 불일치 시(S14 시나리오: T가 과거 기록 재작성 시도) 연결선이 붉은색 파단선(`--fail`, 점선)으로 끊어지며 경고 표출.
2. **Anchor Pinning (과거 체크포인트 고정핀)**:
   - 과거 사용자 PC에 저장된 체크포인트나 목격자 W의 앵커(`tree_size: N`) 위치에 핀 아이콘 배치.
   - "이 시점 이전의 잎들은 Merkle 일관성 증명(RFC 9162)을 통해 변경되지 않았음"을 시각적 자물쇠(Lock) 띠로 묶어 표현.
3. **Leaf Ribbon (진술 잎 리본)**:
   - 로그의 각 진술(0: 정책, 1: 계약, 2: 중계, 3: 영수증...)을 순차적 체인 카드로 나열.
   - 잎에 마우스를 올리면 해당 진술 유형(CT_POLICY, CT_RECEIPT 등)과 서명자 ID 툴팁 표출.

### 3.2 판정 대조기 (`VerdictComparator`)
1. **Side-by-Side 판정 카드**:
   - `T의 등록 판정` vs `감사자의 재계산 판정`을 1:1로 비교.
   - 일치하는 요청은 컴팩트하게 축약(`sub`, 일치 뱃지, 소요 시간).
2. **불일치(Mismatch) 발생 시 상세 Expander**:
   - T가 거짓으로 '통과'를 발행했으나 감사자 엔진이 '위반'을 도출한 경우(S13), 해당 카드가 붉은색 테두리로 강조되며 `t_verdict`와 `recomputed` 사이의 차이점(Diff)을 한글로 명시:
     `"T의 판정: 정상 통과 | 감사자 판정: E10 종단 응답 불일치 (R의 변조)"`

### 3.3 양방향 동기화 인터랙션 (Bidirectional Synchronization)
1. **Graph → JSON**:
   - 사용자가 좌측 그래프에서 앵커 핀을 클릭하면, 우측 JSON 인스펙터가 `anchors[0]` 위치로 부드럽게 스크롤(ScrollIntoView)되고 해당 JSON 라인들이 2초간 은은한 하이라이트 배경색(`var(--accent-soft)`)을 띰.
   - 좌측에서 특정 판정 불일치 카드를 클릭하면 우측 `verdict_mismatches[i]` 블록으로 포커스 이동.
2. **JSON → Graph**:
   - 우측 JSON 트리에서 마우스를 특정 키(예: `"recomputed_root"`)에 올리면 좌측 다이어그램의 해당 재계산 노드가 부드럽게 펄스 발광.
3. **1클릭 복사 및 축약**:
   - 64자리 긴 SHA-256 해시는 기본적으로 앞 12자리(`short(h)`)만 표시하고, 클릭 시 전체 해시 클립보드 복사 및 `복사됨` 미니 토스트 알림.

## 4. 구현 단계별 가이드 (Implementation Steps)

1. **DOM 구조 개편 (`desktop/index.html`)**:
   - `#audit-content` 내부를 좌우 분할 그리드(`.audit-split-grid { display: grid; grid-template-columns: 1.1fr 0.9fr; gap: 16px; }`)로 변경.
2. **시각화 렌더러 (`desktop/src/audit-view.ts`)**:
   - `renderMerkleBridge(anchorData, treeOk)`: SVG/HTML 기반 머클 헤드 및 앵커 핀 다이어그램 렌더링.
   - `renderVerdictDiff(checkedVerdicts, mismatches)`: 판정 대조 리스트 렌더링.
3. **JSON 맵퍼 컴포넌트 (`renderMappedJson(auditJson)`)**:
   - 단순 `<pre>` 대신 키-값 단위로 `data-json-path="anchors.0.root"` 속성을 가진 구조화된 DOM 생성.
   - 이벤트 리스너를 통해 좌측 요소의 `data-ref-path`와 우측 요소 매핑.
4. **스타일 정의 (`ui/console.css` — 데스크톱과 보고서가 함께 읽는다; 앱 전용 규칙만 `desktop/src/style.css`)**:
   - 앵커 핀, 머클 노드 카드, 네온 하이라이트 애니메이션 추가.
